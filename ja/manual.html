DeskPort とは

  1. DeskPort は 1 台のコンピュータを共有し、ほかのデバイスからそのデスクトップを使えるようにします。
  2. 使われる側のコンピュータがホスト、手元で操作するデバイスがクライアントです。1 台で両方を兼ねることもできます。
  3. デバイス同士の連携は一度だけです。アクセスはホストで許可し、ホストで取り消せます。
  4. DeskPort は保存済みのデバイスと設定をこのデバイスに保存します。DeskPort アカウントは必要ありません。

このコンピュータを共有する

  1. 上部バーの「共有」を開き、「共有を開始」を選びます。
  2. 求められたら画面収録とアクセシビリティの権限を許可します。許可しなくても共有は始まりますが、画面や入力が動作しません。
  3. 共有アイコンの下の点は、このコンピュータが共有中であることを示します。
  4. macOS で画面が映らない、またはリモート操作ができない場合は、システム設定の「画面収録」と「アクセシビリティ」を確認してください。「共有」には権限と共有の準備状況の確認結果が表示されます。
  5. DeskPort のウィンドウを隠すと、バックグラウンドで共有を続けられます。このコンピュータへのデスクトップ接続を受け付けないようにするには、「共有を停止」を使います。

コンピュータに接続する

  1. 同じネットワークのデバイスは自動的に一覧に表示されます。
  2. 別のネットワークのコンピュータは、追加カードの「デバイスを追加」からアドレスを入力します。
  3. 初めてデバイスを選ぶとホストにアクセスを申請します。ホスト側で許可してください。
  4. すでに別のデバイスが接続中なら、引き継ぐか確認されます。引き継ぐとそのデバイスは切断されます。
  5. 別のネットワークに接続するには、独自の VPN や Tailscale ネットワークなど、両方のデバイス間で通信できる経路が必要です。アドレスを追加するだけでは経路は作成されません。
  6. デバイスカードのメニューの「アドレスを変更」では、複数のアドレスを1行に1つずつ入力できます。ポートはすべてペアリング時のものを使います。DeskPort はこれらを同時に試し、応答したもののうちリストで最も上にあるものを使います。LAN のアドレスを先頭に、ドメインや VPN のアドレスをその後に置いてください。接続中でも変更できます。開いているセッションは現在のアドレスのまま続き、次の接続から新しいリストが使われます。
  7. Sunshine や DeskPort の連携機能がないホストには、「従来のホストを追加」と PIN によるペアリングを使います。PIN を承認できるよう、ホスト側の画面を開いたままにしてください。
  8. 操作権限を取り消すには、共有するコンピュータの「共有」で保存済みのアクセス許可を削除します。「デバイス」からカードを削除する操作とアクセス許可の取り消しは別です。2 台のコンピュータの連携を解除する場合は、両方向の許可を削除してください。

デバイス一覧を整理する

  1. 上部バーの「編集」で編集モードに入り、カードをドラッグして並べ替えます。
  2. デバイスを別のデバイスに重ねるとグループになります。スマートフォンのホーム画面のフォルダと同じです。
  3. カードのメニューの「別名を設定」は、この端末でだけ名前を変えます。
  4. 更新すると保存済みのデバイスを確認し直し、新しいデバイスを探します。
  5. デバイスカードのメニューを開くと、状態やアドレスを確認し、接続操作ができます。「アドレスを変更」は保存済みの接続情報を更新します。別名を設定してもリモートコンピュータ自体の名前は変わりません。

ウィンドウとバックグラウンドセッション

  1. デスクトップでは、ビューアーを閉じたり隠したりしても、セッションはバックグラウンドで接続を維持します。「切断」はその接続を終了し、「終了」は DeskPort を終了します。
  2. トレイメニューやデバイス一覧から、接続中のデスクトップを再表示できます。複数のセッションがある場合は、セッションメニューで目的のものを選びます。
  3. ビューアーを隠すか別のウィンドウにフォーカスを移すと、リモート側で押されていたキーやボタンが解放されます。リモートセッションの接続を維持したまま、ローカルコンピュータを使えます。
  4. 接続をやり直す場合や保存済みの配信設定を適用する場合は、デバイスメニューの「再接続」を使います。

デスクトップのキーボードショートカット

  1. Meta + ' で DeskPort の表示と非表示を切り替えます。macOS では Command + '、Windows では Windows + '、Linux では Super + ' を使います。キーを離すと実行されます。選択中のセッションを再表示し、接続中のセッションがなければ「デバイス」を表示します。
  2. 設定 → キーボードショートカット → ウィンドウのグローバルショートカット は既定でオンです。オフにすると、システムへのキー割り当てを解除し、ビューアー側の代替処理も直ちに無効にします。この選択はこのコンピュータに保存されます。
  3. 設定 → キーボードショートカット で、「ウィンドウのグローバルショートカット」の行にある現在のキーの組み合わせをクリックします。キーの組み合わせを押すか「キーを選択」で指定し、保存します。新しい割り当てはこのコンピュータですぐに有効になります。「既定に戻す」で Meta + アポストロフィー（'）（macOS では Command + アポストロフィー）に戻ります。「キャンセル」では以前の割り当てを維持します。キーの記録中はグローバルショートカットが一時停止します。
  4. KDE Plasma では、通常 Meta+1–9 がタスクマネージャーの項目に割り当てられています。キーの記録が反応しない場合は、「キーを選択」で組み合わせを指定してください。保存時にデスクトップ環境から競合の解消を求められる場合があります。別の組み合わせを選ぶこともできます。
  5. Wayland では、デスクトップ環境が許可を求め、キーの割り当てを選択させる場合があります。デスクトップ環境で選んだショートカットが優先されます。登録が拒否された場合、未対応の場合、またはすでに使用中の場合は、トレイやデバイス一覧を使ってください。DeskPort はほかのアプリの割り当てを置き換えません。
  6. デスクトップ接続中は、Ctrl+Alt+Shift+Z でリモート入力の解放と再取得、X で全画面の切り替え、N で次の接続中のデスクトップへの切り替えができます。各文字キーを押すときは Ctrl+Alt+Shift を押したままにします。
  7. Ctrl+Alt+Shift+S で配信統計の表示を切り替えます。D はビューアーの最小化、M はポインターモードの切り替え、C はデスクトップモードでのローカルポインターの表示切り替え、L はポインターを画面内に制限する設定の切り替えです。
  8. Ctrl+Alt+Shift+V はローカルのクリップボードのテキストを、キー入力として送信します。Q はまず全画面を解除し、ウィンドウ表示で再び Ctrl+Alt+Shift+Q を押すと切断します。

フルスクリーン

  1. デスクトップでは、デバイス設定 → 配信の詳細設定 → 接続ウィンドウ で、次の接続に使う「ウィンドウ」「フルスクリーン」「ボーダーレス全画面」を選びます。
  2. コンピュータでは接続中に Ctrl+Alt+Shift+X で全画面を切り替えます。スマートフォンやタブレットではフローティングボタンが戻ります。
  3. スマートフォンやタブレットでは、リモートデスクトップは常に画面全体に表示されます。フローティングボタンをタップするとキーボード、長押しするとメニューが開きます。
  4. ホストは接続中のデバイスに全画面の解除を求められますが、全画面を強制することはありません。

画質と仮想ディスプレイ

  1. リモートデスクトップはウィンドウの大きさに合わせるので、ウィンドウを変えるとリモート側も変わります。
  2. 仮想ディスプレイでは、接続中にホスト自身の画面をどう扱うかを決めます。
  3. デスクトップ微調整で、リモートデスクトップ上の表示全体を大きくしたり小さくしたりできます。
  4. これらの設定はデバイスごとに保存されます。
  5. 「ウィンドウに合わせる」はビューアーの描画可能なピクセル数に合わせます。オフにすると保存済みの解像度を使います。利用できるデスクトップサイズや拡大率はホストによって異なります。
  6. 「デスクトップ微調整」は、1.5 で操作部品が大きくなり、0.5 でより多くの内容を表示できます。接続中に反映されます。ホストの最小サイズの制約でそれ以上拡大できない場合は、ウィンドウを大きくするか全画面を試してください。
  7. 「メイン + ミラー」はリモートの作業領域を複製し、「メインのみ」はホストのほかの画面をオフにし、「拡張画面」は作業領域を追加します。対応状況はホストによって異なります。セッション終了時には以前の画面配置に戻ります。

キーボード、ポインター、クリップボード

  1. デバイス設定 → 入力 では、キーボード、ポインター、コントローラーの操作を送信するかどうかを設定します。閲覧だけの場合はオフにします。受信する音声は「サウンド」で別に設定します。
  2. 配信の詳細設定 → キーボードとポインター には、ポインターモード、スクロール方向、システムショートカットの転送、セッションのクリップボード共有があります。
  3. Mac ホストでは、Super / Windows は Command、Alt は Option に対応します。一部のショートカットは OS が使用する場合があります。Ctrl+Alt+Shift+Z で入力先をローカルコンピュータに戻せます。
  4. 「ローカルの入力メソッドを使用」は既定でオフです。デバイスごとに有効にして再接続すると、このコンピュータの IME で文字を入力できます。候補はリモート側の入力位置ではなく左上付近に表示されます。ゲームなどでは、必要に応じてリモート側の IME や物理キーを使ってください。
  5. セッションのクリップボード共有は、両方のデバイスが対応していれば、テキスト、画像、ファイルを扱えます。コピーと貼り付けができない場合は、セッションの接続を維持し、両側でこのオプションを確認してください。
  6. デバイスの配信設定の変更は、ほとんどが再接続後に反映されます。「デスクトップ微調整」はセッション中に反映され、外観とウィンドウのグローバルショートカットはすぐに反映されます。

画質、サウンド、データ使用量

  1. 「配信の詳細設定」には、「自動」「鮮明さ優先」「滑らかさ優先」「データ節約」「カスタム」の画質モードがあります。「自動」は解像度に応じて帯域幅を選び、ネットワークの状況に合わせて調整します。
  2. 「データ節約」は 30 fps、映像の上限 5 Mbps で動作します。上部バーの「データセーバー」スイッチはすべてのデバイスに適用されます。音声やプロトコルの通信量は別に加わります。
  3. 高いフレームレートや広い帯域幅には、より多くのネットワーク容量と処理能力が必要です。動きが途切れる場合や入力に遅延を感じる場合は、これらを下げて配信統計を確認してから画質を上げてください。
  4. サウンドのオプションには、DeskPort がフォーカスを失ったときのミュートと、ホストでも音声を再生する設定があります。音が出ない場合は、デバイスの「サウンド」スイッチ、フォーカス喪失時のミュート、両方のコンピュータの音声出力を確認してください。

ブラウザーから接続する

  1. デスクトップホストで 共有 → ブラウザーアクセス を開き、表示された URL をほかのデバイスでスキャンするか開きます。接続する前に共有を開始してください。
  2. ホストまたは認証アプリに表示される 6 桁のコードを入力します。コードは 30 秒ごとに変わります。同じ Tailscale アカウントにログインしていると認識されたデバイスは、コードなしで接続できます。
  3. 接続するデバイスで、ホストのローカル HTTPS 証明書を信頼する必要があります。信頼する前に、URL と証明書が自分のホストのものか確認してください。
  4. 「このブラウザを 7 日間記憶します」を有効にすると、そのブラウザーでは以後のコード入力を省略できます。許可を取り消すには、「共有」でペアリング済みのブラウザーを削除します。認証アプリ用の QR コードは公開しないでください。シークレットをリセットすると、設定済みの認証アプリは無効になります。

設定、プライバシー、フィードバック

  1. 「設定」では、このコンピュータのテーマ、アクセントカラー、言語、上部バーのデータ使用量表示、ウィンドウのグローバルショートカットを設定します。「デバイス設定」では、保存済みの接続を個別に設定します。
  2. 診断ログは既定でオフです。問題を再現する前に、設定 → 診断とフィードバック で有効にしてください。共有する操作を行うまで、ログはこのコンピュータ内に保存されます。
  3. 「問題を報告」は ZIP を作成し、GitHub の issue の下書きを開きます。アップロードや送信は自動では行いません。公開 issue に添付する前に、アーカイブの内容を確認し、手順、使用したシステム、期待する動作を記述してください。
  4. 診断をオフにすると新しい記録が停止します。「保存した診断データを削除」は既存のログと作成済みの ZIP を削除します。「設定」の「プライバシー」と「ライセンス」では、記録するデータと同梱ソフトウェアについて説明しています。

うまくいかないとき

  1. オフラインと表示されるデバイスは、たいていスリープ中、別のネットワーク、または共有していない状態です。
  2. 上部バーの「更新」で、保存済みのすべてのデバイスを確認し直します。
  3. 設定の「問題を報告」でログのアーカイブを作成し、issue に添付できます。共有する前に内容を確認してください。
  4. デバイスがオフラインのままの場合は、スリープしていないこと、共有がオンであること、保存済みのアドレスに到達できることを確認してください。再試行する前に、ホストの準備状況とファイアウォールを確認します。「更新」ですべてのホストを起動したり、ネットワーク経路を修復したりできるわけではありません。
  5. 画面が黒い場合は、画面収録の権限と選択中のホストのディスプレイを確認してください。操作できない場合は、「アクセシビリティ」、デバイスの「入力」スイッチ、ビューアーにフォーカスがあるかを確認してください。
  6. ウィンドウのグローバルショートカットが動作しなくなった場合は、「設定」のスイッチ、デスクトップ環境のショートカットの権限、ほかのアプリとの競合を確認してください。一度オフにしてからオンにすると、登録を再要求できます。トレイと「デバイス」は引き続き使えます。
